A disposable model test · 25 September 2026

Three models.
One UFO.

I gave Claude Opus 5.5, GPT-6 Sol and GPT-6 Luna the same loose brief: make a small one-button UFO parking game in Three.js.

They could write files, inspect their own work, run checks and revise it. Here are the games first. The receipts and the slightly messier story are underneath.

What I actually did

The boring bits are useful.

Each run started with the same bundled Three.js file, the same short brief, the same thirteen tools, xhigh reasoning and a 128,000-token output ceiling. The model could use a writable project folder. The shell ran in a network-disabled Node container. A separate package installer was available if a model chose to use it.

Media tools were optional. None of the three asked for image, SFX, video or Blender output. Opus made one music loop and two voice clips. Its two extra voice requests were rejected by the per-run call limit. Sol and Luna made their visuals and sounds in code.

The checks cover file references, JavaScript syntax, Three.js loading and keyboard/pointer handlers. They do not prove WebGL rendering, accessibility or game feel. This is one run per model, so I am not calling a winner from it.
